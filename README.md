Tento lab věnovaný zranitelnosti CSRF (Cross-Site Request Forgery) simuluje obcházení výchozí ochrany `SameSite=Lax` u prohlížečů pomocí techniky **Method Overriding** (přepsání HTTP metody).

## Technical Background & Analysis

### 1. `Set-Cookie` Attributes: `Secure` a `HttpOnly`
Při přihlášení uživatele (`wiener:peter`) server v odpovědi nastavil session cookie s těmito atributy:
* **`Secure`**: Zajišťuje, že se cookie přenáší výhradně přes šifrovaný protokol HTTPS. Zabraňuje odposlechu na nešifrovaných sítích.
* **`HttpOnly`**: Zabraňuje přístupu k dané cookie pomocí klientských skriptů (např. přes JavaScript `document.cookie`). Chrání session před odcizením v případě zranitelnosti XSS.

### 2. Status `SameSite` atributu
Při inspekci vývojářských nástrojů (F12 -> Application -> Cookies) byla hodnota `SameSite` prázdná. 
* **Mechanismus:** Moderní prohlížeče (Chrome) v takovém případě automaticky aplikují výchozí chování **`SameSite=Lax`**.
* **Důsledek pro CSRF:** V režimu `Lax` prohlížeč **neodesílá** cookies u cross-site požadavků (např. z exploit serveru na aplikaci), pokud je metoda požadavku `POST`. Tím standardně blokuje klasické CSRF útoky měnící stav.

# Deep Dive: Why Did This Work?
1. Proč se měnila metoda na GET?
Prohlížeče blokují odesílání SameSite=Lax cookies u cross-site POST požadavků. U GET požadavkůvyvolaných top-level navigací však prohlížeč session cookie přibalí a odešle. Změna metody formuláře na GET obchází restrikci prohlížeče.

2. Proč byl přidán parametr _method=POST?
Samotný GET požadavek aplikace odmítla (405 Method Not Allowed), protože očekává změnu stavu přes POST.

Mnohé backendové frameworky umožňují tzv. Method Overriding pro klienty, kteří nepodporují všechny HTTP metody.

Přidáním parametru _method=POST backend přečte požadavek, který přišel jako GET, ale interně ho předá controlleru jako POST.

3. Sled událostí při útoku:
Prohlížeč oběti vykoná GET požadavek na zranitelnou aplikaci.

Jelikož jde o GET, prohlížeč přibalí session cookies oběti (obcházení SameSite=Lax).

Server přijme GET požadavek, přečte parametr _method=POST, interně přehodnotí požadavek na POST a vykoná změnu e-mailu na evil@abnormal-user.net


### Podrobný význam kódu `<input type="hidden" name="_method" value="POST">`

Tento HTML kód slouží k tzv. *method overriding* (přepsání HTTP metody) na straně serveru. Skládá se ze čtyř klíčových částí:

1. **`<input>`**: 
   * Základní HTML prvek, který se ve formulářích používá k odesílání dat na server.

2. **`type="hidden"`**: 
   * Tento atribut zajišťuje, že prvek je **skrytý**. Uživatel ho na webové stránce vůbec nevidí a nemůže do něj nic psát. Přesto se jeho hodnota odesílá na server spolu s celým formulářem na pozadí.

3. **`name="_method"`**: 
   * Definuje **název parametru**, který backend aplikace vyhledává. Mnoho webových frameworků sleduje právě tento název, aby zjistilo, zda má změnit způsob zpracování HTTP metody.

4. **`value="POST"`**: 
   * Nastavuje **hodnotu** tohoto parametru. Serveru tím říká, že i když požadavek mohl přijít například jako `GET`, má ho interně zpracovat jako metodu **POST**.
